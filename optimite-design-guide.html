Every designer was working from memory.

Optimite manages email design for a growing portfolio of brands — each with its own logo, colour system, typography, padding rules, tone of voice, and visual references. As the team scaled, a structural problem became impossible to ignore.

There was no single source of truth. When a designer started a new campaign, they either asked a colleague, dug through old Figma files, or made educated guesses. Brand consistency was entirely dependent on individual memory. Account managers reviewing designs had no structured checklist — reviews were subjective and inconsistent.

I identified this as the highest-leverage problem I could solve. Not a template. Not a guideline document. A living, functional tool that every role could use — and that could eventually power AI-generated design output directly.

What I built

Six layers. One pipeline. Zero guesswork.

I designed, built, and deployed the system entirely solo — from database architecture to live Vercel deployment. The tool is structured around a per-brand model: each brand has its own guide, asset library, and AI output layer.

Layer 01
01
Brand Guide
A structured, always-current reference for every brand — accessible in seconds, no searching required.
Brand identity: logo display, brand story, visual direction and tone
Layout specs: container width, padding rules, logo count and placement
Colour system: primary, secondary, accent, and background values with hex codes
Typography: heading and body font families, weights, and size scales
Dos and Don'ts: explicit rules for what is and isn't on-brand per client
Reference emails: screenshot library of approved past campaigns
Layer 02
02

Logo uploads with active/inactive tagging — always the correct version

Reference email screenshots uploaded and organised per brand
Assets in a dedicated Supabase table, separate from structured data — avoids row size limits

Technical decisions

Built to last, not just to ship.

Building solo meant every architectural decision had a direct consequence on reliability. These are the choices that shaped the system.

Database
Separate assets table in Supabase
Keeping logos and fonts out of the main brand rows avoided row size limits and silent failures I encountered early in development. Binary assets live in a dedicated table — structured data and files never mix.
API Security
Vercel Edge Functions as API proxy
Direct browser-to-Anthropic API calls fail due to CORS and expose credentials. All AI calls route through a serverless function, keeping the API key server-side and the client clean.
Reliability
Conservative max_tokens on all API calls
JSON truncation from insufficient token limits caused hard-to-diagnose bugs early on. Raising limits and adding fallback parsers resolved this. Now all calls have headroom built in by default.
Deployment
GitHub auto-deploy to Vercel
Every push to the repo auto-deploys to Vercel. Iteration is fast, the codebase is version-controlled, and there's no manual deployment step — which matters when you're building and maintaining solo.
What I learned

On building systems alone.

1
Define before you build
The hardest part of building internal tools isn't the build — it's defining exactly what the tool needs to do before you write a line of code. The brand guide structure went through three iterations before the right information architecture emerged.
2
AI QA is only as good as the data behind it
The evaluator is only as good as the brand spec it checks against — which made the guide-building phase the most important part of the entire project. Garbage in, garbage out applies to AI-powered tools more than anywhere else.
3
Separate assets from structured data
Early Supabase row size errors taught me this the hard way. At scale, binary files and structured records need to live separately. This is now a default assumption in how I architect any data-driven tool.
4
End-to-end ownership changes how you decide
Building the database, the UI, the API integration, and the deployment pipeline alone meant I understood every failure mode — and could fix them without waiting on anyone. Ownership and accountability are the same thing when you're the only person in the room.
